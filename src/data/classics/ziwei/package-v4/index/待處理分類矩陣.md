# 待處理分類矩陣

本矩陣的目的，是讓 pending 不再只是「還沒做」，而是明確說明為什麼不能啟用。

| 類別 | 定義 | 可否進 enabled rule |
|---|---|---|
| `verifiedClear` | 原頁清楚、逐字核對無疑字、條件完整 | 可 |
| `visualDraftNeedsSecondPass` | 已人工轉錄，但尚未第二次獨立複核 | 不可或只低信心 |
| `unclearGlyph` | 存在一個以上疑字，且疑字會改變條件／結論 | 不可 |
| `conditionIncomplete` | 古文只列名稱或結論，未提供足夠成立條件 | 不可；只能 PatternCandidate |
| `secondaryLowResolution` | 只有低解析第二來源，無法逐字核對 | 不可作 primary evidence |
| `ocrSearchOnly` | 僅機器 OCR 命中 | 不可 |
| `historicalOnly` | 壽夭、疾病、貧賤、性別角色等歷史性斷語 | 可存在 classical layer；不可直接現代斷語 |
| `calculationReference` | 安星、五行局、起例等客觀排盤資料 | 不進 Interpretation，除非用來校驗 engine |

## 目前各區建議分類

- p17-p20：以 `conditionIncomplete` / `visualDraftNeedsSecondPass` 為主，逐條清理後啟用。
- p21-p25：多數 `calculationReference`。
- p26-p31：十四主星 locator 為 `verifiedClear`；完整段落多數仍需 `visualDraftNeedsSecondPass`。
- p32-p36：輔煞、化曜等需逐星拆；不得批量 OCR。
- p37-p44：十二宮章首／範圍多數 `verifiedClear`；宮內逐星斷語仍需分條校。
- p45-p47：數條短總則可達 `verifiedClear`；長段／強烈宿命語義要做中性化與條件化。
- p48-p55：結構清楚，但屬 `columnWiseRequired`，不得一次 bulk enable。
